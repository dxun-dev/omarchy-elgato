Please review the registry's manual installation override. The plugin already
supports this complete end-user entry point:

omarchy plugin add https://github.com/dxun-dev/omarchy-elgato.git --enable

Service.qml starts bin/omarchy-elgato daemon. Before requiring Node.js, the Bash
launcher checks system requirements and opens a confirmation terminal when
needed. On confirmation, scripts/system-setup.sh installs missing packages via
omarchy pkg add, installs the narrowly matched udev rule using sudo, enables
Avahi when inactive, and resumes the service through shell IPC. Runtime setup
runs npm ci --omit=dev outside the plugin directory and verifies native modules.
The compiled backend is shipped. Users do not need manual clone/build/npm/setup
commands; they do need setup consent, administrator authentication when needed,
and internet access. Optional applications such as VOXtype are not installed.

main's README and site's getting-started guide now have matching install/update/
removal guidance and file inventories, including package-owned files and caches,
udev rules, Avahi unit links/runtime files, Omarchy shell config, plugin source,
profile migration backups, runtime dependencies, logs, and local/removal backups.
These documentation changes and a new missing-Node bootstrap regression test
are local and must be published before requesting verification of a newer SHA.
